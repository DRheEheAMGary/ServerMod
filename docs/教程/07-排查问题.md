# 07 · 排查问题

按"现象 → 原因 → 处理"组织。**先做这两件事**：

1. 看控制台（日志前缀是 `(HubSuite)`）
2. 跑 `hub selftest` —— 110 项会直接告诉你哪一环坏了

---

## 进不去 / 连不上

### 连上就被踢，提示"配置时出现意外错误"

**原因**：这是**客户端在配置阶段**收到的错误，几乎都是模组的 Mixin 挂了。
典型来源是 `PrepareSpawnTaskMixin`（登录出生点重定向）匹配错了目标。

**处理**：看服务端日志有没有 `ClassCastException` / `InvalidMixinException`。
把报错原文发出来。临时绕过可以让玩家删掉那个 Mixin 重新编译。

### 一直在"正在连接服务器"

**原因**：服务端主线程被卡住了（区块生成、同步 IO）。
**处理**：看日志有无 `A single server tick took 60.00 seconds` —— 见下面「服务器卡死」。

### 进服后弹不出注册框

**原因**：客户端装了屏蔽自定义界面的模组。
**处理**：用聊天兜底命令：

```
/register <密码> <确认>
/login <密码>
```

---

## 登录/账号

### 提示"该名字已注册"但我不认识这个人

离线服里名字就是身份。可能是有人抢注了。
**处理**：管理员 `/auth reset <玩家> <新密码>` 拿回账号。

### 改了密码，之前登录的人还在线

已修：`/auth reset` 和 `/auth delete` 现在会**作废该账号的全部会话**。
如果你的版本还会出现，说明是旧版。

### 玩家被锁了（失败 5 次）

默认锁 10 分钟。管理员可以立即解锁：

```
/auth reset <玩家> <新密码>     # 重置并自动解锁
```

## 切服 / 数据

### `/hub` 之后进不去别的子服

先确认服务端日志有没有这三行：

```
切服请求：<玩家> -> <目标>
切服完成：<玩家> 现在位于 <目标>
```

- **三行都在，但客户端没反应** → 客户端侧问题（区块加载慢、卡界面），
  让玩家发 F3 坐标
- **只有"切服请求"，没有"切服完成"** → 传送过程中抛异常了，日志里会有堆栈

### 背包/物品没跟过来

**这是设计** —— 每个子服独立背包。

- 在大厅 → 背包应该是**空的**
- 回生存服 → 物品应该**还在**

如果回原服务器物品没了，是状态暂存出了问题。检查日志有无
`暂存 ... 的状态失败` / `套用 ... 的状态失败`。

### 玩家数据写到了主世界存档

**正常情况不该发生。** 检查：

```bash
ls run/world/players/data/*.dat        # 应该是空的
ls run/hubsuite_survival/players/data/ # 玩家数据应该在这
```

如果有数据落到 `world/`，说明玩家数据路由失效了 ——
把 `hub selftest` 的输出发出来，里面有专门的检查项。

### 成就/统计串味

**已于 2026-10 修复**：成就与统计现在也按子服维度隔离，
存在 `<子服存档>/players/data/{stats,advancements}/`。

> **升级注意**：旧的全局文件（`run/world/players/stats/`）**不会自动迁移**。
> 升级后玩家首次进各子服时成就从空白开始。
> 要保留旧进度就手工复制：
> ```bash
> cp run/world/players/stats/<uuid>.json run/hubsuite_survival/players/data/stats/
> ```

## 服务器卡死

### 日志出现 `A single server tick took 60.00 seconds`

**这是看门狗强杀**。几乎总是同一个原因：

> **在主线程上对未加载的区块做 `getBlockState` / `setBlockAndUpdate` / `getChunk`。**

这三个方法在区块未加载时都会**同步生成整片区块**并原地等待。
海洋地形尤其重，一次就能卡满 60 秒。

**排查**：崩溃报告 `run/crash-reports/` 里搜 `hubsuite`，
找**非关服路径**的那一帧（关服栈是 `onServerStopping`，不是元凶）。

**处理**：
- 如果是模组代码的问题 → 应该用 `level.getChunkSource().hasChunk(x, z)` 先探测，
  未加载就跳过、登记待办、下一 tick 重试（本项目所有涉及区块的代码都该这么写）
- 如果是**你自己用 `/forceload` 或命令**在重维度里预加载区块 → 那是操作导致的，
  不要在海洋维度用 forceload

### 启动特别慢

首次启动要新建所有世界 + 用原版算法算出生点（最多 121 个区块的螺旋搜索）。
实测 5 个新维度约 3 秒，属正常。

后续启动会用**缓存的出生点**，快很多。缓存绑定了种子，换种子会自动重算。

## 空岛

### 一直往下掉 / 岛没生成

地形是**延迟生成**的：建岛时玩家还在旧维度，区块必然未加载，
强行生成会卡死主线程。所以系统会登记待办，等玩家落到岛上后（区块自然加载）
再补铺。

看日志应有：
```
方格(x, z) 的区块还没加载，地形稍后补铺（避免阻塞主线程）
方格(x, z) 的地形已补铺完成
```

如果只有第一行没有第二行，说明区块始终没加载 —— 检查玩家是不是根本没到那座岛。

### 提示"这不是你的区域"

保护判定：

- 经典空岛：按**方格**判定，你自己方格内到处都能建
- 海岛：按**离岛的距离**判定，岛之外的海面是公共区域

如果你在自己家角落被拒，是保护半径没覆盖到（已修：现在按外接圆半径判定）。

### `/island` 说"请先进入空岛服"

**已于 2026-10 修复**。原因是拿子服**主维度**去比较，
而玩家实际只在 `skyblock_hub/_classic/_ocean` 三个维度里，永远不相等。
现在改成遍历子服全部维度判定。

## 任务

### 挖了方块但任务进度不涨

1. **必须在空岛相关维度里**（大厅 / 经典空岛 / 海岛）——
   在生存服挖石头不计入空岛任务，这是刻意的
2. 打开任务界面看进度条是否真的没动
3. 看日志有无 `推进任务进度失败`

### 任务界面是空的

看启动日志有没有 `任务系统已就绪：N 个任务`。
如果显示 0 个，说明配置里的 `quests.quests` 是空的。

### 改了任务配置没生效

任务管理器在**启动时**构建。`/hub reload` 只重读配置对象，
**建议重启服务端**。

## 假人（NPC）

### 假人不见了

看启动日志有没有 `大厅引导假人已就绪：N 个`。
如果是 0 个，检查 `config.lobby.menuNpc.enabled`。

### 假人出现在 Tab 列表里

**已于 2026-10 修复**。原版 `ClientboundPlayerInfoUpdatePacket.Entry`
把 `listed` 字段**硬编码为 true**，所以只设 `allowsListing=false` 没用，
必须 Mixin 改字段。

### 点假人没反应

假人只对**已认证**玩家响应。未登录时点击会提示"请先完成注册或登录"。

### 从存档里看群系，发现海洋维度里全是 plains

**这不是 bug，别被它骗了。** 直接读 region 文件统计群系时，会看到大片
`minecraft:plains`（实测占 58%），而那其实是**没生成完的区块**：

| 区块 Status | 群系字段 | 含义 |
|---|---|---|
| `minecraft:structure_starts` | `plains` | 只算完结构起点，`BIOMES` 这一步还没跑 |
| `minecraft:biomes` 及之后 / `full` | 真实海洋群系 | 群系已按噪声源填好 |

区块在构造时群系容器先填默认值 `minecraft:plains`，要等生成流程走到 `BIOMES`
那一步才会被真正的群系源覆盖。这些半成品区块会被落盘，玩家开船过去时会从
`structure_starts` 继续跑完，群系**会**被正确填充。

想准确统计群系，有两个办法：

1. 看 `Status` 字段，只统计 `biomes` 及之后的区块；
2. **问群系源**（推荐，也是自检的做法）：`level.getNoiseBiome(x >> 2, y >> 2, z >> 2)`
   —— 只读噪声、不碰区块数据，也不加载区块。

> 同类陷阱：别直接 `compute` 密度函数来读温度/大陆性。原版那些函数外面包着
> `flat_cache` / `cache_2d`，缓存要靠 `fillArray` 初始化，直接算只会拿到 0
> （实测量出过"温度范围 0.00~0.00、100% 落在温和带"这种鬼数据）。
> 正确做法是问 `level.getChunkSource().randomState().sampler()`。
