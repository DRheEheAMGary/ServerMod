## 自检是你的主要工具

```
hub selftest             # 控制台（需要 OP 或控制台身份）
/hub selftest            # 游戏内
```

**110 项**，覆盖：

- 存档隔离（每个子服目录独立）
- 规则隔离（gamerule 互不影响）
- 玩家数据隔离（**落盘位置 + 跨服往返**）
- 成就/统计隔离
- 账号安全（注册/登录/锁定/重置）
- 空岛生成、保护、入口分流
- 任务逻辑（推进/领奖/交付扣物品/防重复领奖）
- 指令注册与可执行性
- 集成适配（HuskHomes / 占位符 / 权限）

**改完代码先跑自检。** 多世界隔离这类东西光看代码确认不了 ——
本项目好几个真 bug（玩家数据写进主世界、`/island` 全是死指令）
都是自检抓出来的，不是看出来的。

## 铁律：不要在未加载的区块上读/写方块

**这是本项目最容易犯、后果最严重的错误。** 累计被看门狗强杀过四次。

以下三个方法在区块未加载时都会**同步生成整片区块**，主线程原地等待：

```java
level.getBlockState(pos)        // ❌ 未加载时同步生成
level.setBlockAndUpdate(pos, s) // ❌ 同上（内部 getChunkAt）
level.getChunk(x, z)            // ❌ 同上
```

海洋/正常地形的区块生成很重，一次 3×3 就能卡满 60 秒。

### 正确写法

```java
// 1) 先探测，不触发生成
if (!level.getChunkSource().hasChunk(cx, cz)) {
    // 2) 没加载就跳过，登记待办，下一 tick 重试
    pending.add(...);
    return;
}
// 3) 已加载，这时读方块是安全的
BlockState state = level.getBlockState(pos);
```

本项目已经建立了这个范式，抄这两处：

- `IslandManager.generate()` 的 `chunksReady` 检查 + `pendingTerrain` + tick 重试
- `SubServer` 的 `pendingPlatforms` + tick 重试

### 测群系也要小心

```java
level.getBiome(pos)          // ❌ 可能触发生成
level.getNoiseBiome(qx,qy,qz) // ✅ 纯噪声计算，不生成区块
```

### 自检里同样适用

自检跑在主线程。**不要 `Thread.sleep` 等服务**（占住主线程照样触发看门狗），
也不要直接读可能未加载的区块。用 `blockIfLoaded()` 那套写法。

## 指令必须在初始化阶段注册

```java
// ✅ 正确：模组初始化时注册
public void onInitialize() {
    CommandRegistrationCallback.EVENT.register((dispatcher, registry, env) -> {
        dispatcher.register(...);
    });
}

// ❌ 错误：服务端启动后才注册 —— dispatcher 早就建好了，指令根本不存在
ServerLifecycleEvents.SERVER_STARTED.register(server -> {
    dispatcher.register(...);   // 无效！
});
```

**这个坑真实发生过**：`/island` 一度是死指令，输入只报
`Unknown or incomplete command`，因为它在 `SERVER_STARTED` 里注册。

如果指令依赖运行时才有的对象（比如 `IslandService`），用 **supplier 延迟解析**：

```java
new IslandCommand(() -> islands, permissions).register();   // 执行时再去拿
```

## 没有"卸载维度"这回事

`MinecraftServer.levels` 是启动时一次性建立的**只读映射**，
**运行时无法卸载或新建维度**。

所以：

- 新增/删除子服 → **必须重启**
- "重置地图"类操作 → 只能删磁盘存档，重建交给下次启动
- 不要在 `SERVER_STOPPING` 里提前把维度从 `levels` 摘掉 ——
  原版随后的"等待区块排空 → saveAllChunks → level.close()"会看不到它们，
  RegionFile 句柄一直开到 JVM 退出

**关服两阶段的正确顺序**：

```java
SERVER_STOPPING.register(...)  // 只主动落盘，不要拆任何东西
SERVER_STOPPED.register(...)   // 原版收尾完成后，才清路由/关存档
```

**踩过的坑**：原来把清理全放在 STOPPING，结果原版随后的
`playerList.saveAll()` 因为路由已被清空，把每个在线玩家的最终状态
写进了**主世界**存档 —— 玩家最后一段游戏成果永久丢失。

## 玩家数据是"三份"，不是一份

原版 `PlayerList` 分别保存：

```java
private void save(ServerPlayer player) {
    this.playerIo.save(player);              // 背包/经验/末影箱
    this.stats.get(uuid).save();             // 统计   → 全局路径
    this.advancements.get(uuid).save();      // 成就   → 全局路径
}
```

后两者的路径来自 `server.getWorldPath(...)`，**与玩家所在维度无关**。
只替换 `playerIo` 是不够的（本项目的 `PlayerListStorageMixin` 干这个，
`PlayerListAuxDataMixin` 补上另外两份）。

而且 `ServerStatsCounter` / `PlayerAdvancements` **把文件路径烧死在字段里**，
所以切换维度时必须把它们从 `PlayerList` 的缓存里移除，否则读写会继续落在旧子服。

## Mixin 注意事项

**helper 类不能放在 `mixin` 包**，否则报
`IllegalClassLoadError: ... is in a defined mixin package`。
本项目的 `ServerInternals` / `PlayerListAccess` / `CommandGuardHolder`
都在业务包，Mixin 只做转发。

**Mixin 类不能有非 private 的静态成员**。需要跨 Mixin 共享状态就抽个 holder：

```java
// ✅
public final class CommandGuardHolder {
    private static CommandGuard guard;
    public static void set(CommandGuard g) { guard = g; }
    public static CommandGuard get() { return guard; }
}
```

**`@ModifyExpressionValue` 要指定 ordinal 当同方法里有多个匹配**。
本项目踩过：`PrepareSpawnTask.start()` 里有两处 `orElseGet`，
不指定 ordinal 会命中坐标那处，导致
`ClassCastException: ServerLevel cannot be cast to CompletableFuture`，
**玩家在配置阶段就被断开**。

```java
@At(value = "INVOKE", ordinal = 0, target = "...Optional;orElseGet(...)...")  // ✅
```

**改 record 的字段**：`@Shadow @Final @Mutable` 可以绕过 final，
但要在构造器 `RETURN` 之后改（`ClientboundPlayerInfoUpdatePacket.Entry`
的 `listed` 就是这么修的）。

## 调试技巧

### 日志前缀

统一用 `(HubSuite)`，方便过滤：

```bash
grep "(HubSuite)" run/logs/latest.log | tail -50
```

### 崩溃报告

```bash
ls -t run/crash-reports/*.txt | head -1
```

搜 `hubsuite` 找**非关服路径**的那一帧。关服栈（`onServerStopping`）
是干扰项，不是元凶。

### 看门狗次数

```bash
grep -c Watchdog run/logs/latest.log    # 期望 0
```

### 干净的验证

```bash
# 停服
pkill -9 -f devlaunchinjector
sleep 5
# 全量清空（连地图一起，这是项目约定）
rm -rf run/hubsuite_* run/world run/config/hubsuite
rm -f run/*/session.lock
# 重启
./gradlew runServer
```

> **强杀服务端后必须删 `session.lock`**，否则下次启动会报存档被锁。

### 不要在重维度用 forceload

`/forceload` 在海洋维度会同步加载区块，**本身就会触发看门狗**。
要验证区块相关逻辑，用"让假玩家真的传送过去"的方式。

## 代码地图

```
cn.dreamgary.hubsuite
├─ HubSuite              入口，静态访问器（worlds/auth/quests/islands/...）
├─ world/                多世界引擎
│   ├─ WorldsManager     生命周期、子服集合
│   ├─ SubServer         一个子服（支持多维度：entries）
│   ├─ Lobby / IsolatedSave / WorldBuilder / WorldFactory
│   ├─ PlayerRouter      切服（入口解析→建岛→出生点→传送→绑重生点）
│   ├─ PlayerDataRouter  玩家数据按维度分发
│   ├─ PlayerStateStash  背包/经验按维度暂存
│   └─ AuxDataRouter     成就/统计按维度隔离
├─ auth/                 认证（对话框 + 命令兜底）
├─ island/               空岛（IslandManager 网格与海洋两种放置模式）
├─ quest/                任务系统
├─ ui/                   ChestMenuScreen（箱子界面）/ DialogKit / DialogRouter / Text
├─ npc/                  假人 + 服务器选择界面
├─ feature/              规则引擎、登录锁定、指令闸门、权限
├─ integration/          HuskHomes / 占位符
└─ mixin/                所有 Mixin（只做转发，逻辑放业务包）
```
