# 06 · 写一个对话框

目标：用 26.1 原版对话框做表单，并安全地处理玩家提交。

---

## 1. 原理

对话框是**服务端下发、客户端渲染**的原版机制：

```text
服务端 --ClientboundShowDialogPacket--> 客户端渲染表单
客户端 --ServerboundCustomClickActionPacket--> 服务端（自定义动作 + 表单数据）
```

关键点：表单里的输入值会**按 key 合并进动作的 NBT**，所以 `TextInput` 收集的密码
以该 key 出现在回传数据里，**不进聊天、不进命令、不进日志**。

---

## 2. 最小例子

```java
// 1) 定义动作 id
private static final Identifier ACTION_LOGIN =
        Identifier.fromNamespaceAndPath("hubsuite", "auth/login");

// 2) 注册处理
DialogRouter.register(ACTION_LOGIN, (player, payload) -> {
    String password = payload.getString("password");   // 对应下面 Input 的 key
});

// 3) 弹表单
player.openDialog(DialogKit.form(
        DialogKit.common("§l登录", true, DialogAction.CLOSE),   // 标题 + 关闭行为
        List.of(DialogKit.textInput("password", "§7请输入密码", 32)),
        List.of(DialogKit.submitButton("§a登录", ACTION_LOGIN))));
```

---

## 3. 三个必须注意的点

1. **`after_action` 用 `CLOSE`，不要用 `WAIT_FOR_RESPONSE`。**
   后者会让客户端进入「等待服务器响应」状态，之后约 5 秒点什么都点不动（玩家以为卡死，本项目踩过）。
2. **动作必须走 Mixin 拦截。** Fabric 没有「自定义点击动作」事件，
   用 `ServerCommonPacketListenerMixin` 在 `handleCustomClickAction` 的 `HEAD` 处拦截。
   原版该方法只打一行 debug 日志、不做任何校验 —— 意味着**玩家可以自己构造这个包**，
   所以任何改变状态的动作都要在路由层查权限 / 认证。
3. **回调不要做重活。** 回调在主线程，密码哈希（PBKDF2 一轮约 25ms）、数据库查询要丢到异步线程，
   再 `server.execute(...)` 回主线程操作游戏状态。项目提供 `loginAsync` / `registerAsync`。

---

## 4. 表单元素

| API | 说明 |
|---|---|
| `DialogKit.text(内容)` | 一段文本 |
| `DialogKit.textInput(key, 提示, 最大长度)` | 输入框 |
| `DialogKit.customButton(文字, 动作)` / `DialogKit.submitButton(文字, 动作)` | 按钮 |
| `DialogKit.closeButton(文字)` | 关闭按钮 |
| `DialogKit.form(common, 内容, 按钮)` | 组装表单 |
| `DialogKit.notice(common, 内容, 按钮)` | 通知式表单 |

> 按钮动作必须用 `CustomAll`（`customButton` / `submitButton` 已封装），
> 它把所有输入框的值按 key 合并进 NBT 回传；静态 custom 动作带不回输入值。

读取输入：

```java
payload.getString("my_key");
payload.getInt("count");
payload.getBoolean("confirm");
```

## 5. 调试

- `/hub selftest` 里有一项验证「对话框动作已注册」以及颜色码渲染（`&a` 和 `§a` 都要能出颜色）；
- 表单弹不出来先确认客户端没装屏蔽自定义界面的模组；
- 认证流程保留 `/login` / `/register` 兜底。

## 附录：箱子界面（做「选项列表」更简单更稳）

服务器选择与任务界面都用箱子界面。

```java
ChestMenuScreen.open(player, "§l标题", List.of(
    ChestMenuScreen.Entry.of(new ItemStack(Items.DIAMOND_SWORD), "§f生存服",
        List.of("§7点我进入"), p -> PlayerRouter.sendTo(p, survivalWorld)),
    // ...
));
```

点击由 `ServerGamePacketListenerMenuMixin` 在 `handleContainerClick` 的 HEAD 处接管，
原版逻辑一点都不执行（物品拿不走，shift 点击 / 拖拽 / 数字键无副作用）。

> ⚠️ 玩家退出时要调 `ChestMenuScreen.forget(uuid)` 清理状态，
> 否则 UUID→菜单 的记录一直留着，闭包捕获着 `ServerLevel`。
