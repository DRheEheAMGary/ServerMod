# 06 · 写一个对话框

给开发者：怎么用 26.1 的原版对话框表单做一个自定义界面，并把玩家的输入拿回服务端。

> 如果你想做的是**箱子界面**（选项列表），看 [箱子界面](#附箱子界面) 那节，
> 更简单，本项目的服务器选择界面和任务界面都是这么做的。

---

## 原理

26.1 的对话框是**服务端下发、客户端渲染**的原版机制：

```
服务端  ──ClientboundShowDialogPacket──▶  客户端渲染表单
                                          │
玩家填写 / 点击                            │
                                          ▼
服务端  ◀──ServerboundCustomClickActionPacket──  自定义动作 + 表单数据
```

关键点：**表单里的输入值会按 key 合并进动作的 NBT**，
所以你用 `Input(key, TextInput)` 收集的密码，会以那个 key 出现在回传数据里 ——
**不进聊天、不进命令、不进日志**。

---

## 最小例子

```java
// 1) 定义动作 id
private static final Identifier ACTION_LOGIN =
        Identifier.fromNamespaceAndPath("hubsuite", "auth/login");

// 2) 注册处理
DialogRouter.register(ACTION_LOGIN, (player, payload) -> {
    String password = payload.getString("password");   // 对应下面 Input 的 key
    // ... 校验 ...
});

// 3) 弹表单
player.openDialog(DialogKit.form(
        DialogKit.common("§l登录", true, DialogAction.CLOSE),   // 标题 + 关闭行为
        List.of(DialogKit.textInput("password", "§7请输入密码", 32)),
        List.of(DialogKit.submitButton("§a登录", ACTION_LOGIN))));
```

### 三个必须注意的点

**1. `after_action` 要用 `CLOSE`，不要用 `WAIT_FOR_RESPONSE`**

```java
DialogKit.common(title, canClose, DialogAction.CLOSE)        // ✅
DialogKit.common(title, canClose, DialogAction.WAIT_FOR_RESPONSE)  // ❌
```

`WAIT_FOR_RESPONSE` 会让客户端进入"等待服务器响应"状态，
**之后约 5 秒内点什么都点不动** —— 玩家会以为卡死了。本项目踩过这个坑。

**2. 动作必须走 Mixin 拦截**

Fabric 没有提供"自定义点击动作"的事件，所以本项目用
`ServerCommonPacketListenerMixin` 在 `handleCustomClickAction` 的 HEAD 处拦截：

```java
@Inject(method = "handleCustomClickAction", at = @At("HEAD"), cancellable = true)
private void hubsuite$routeDialogAction(ServerboundCustomClickActionPacket packet, CallbackInfo ci) {
    if (DialogRouter.route(this, packet)) {
        ci.cancel();
    }
}
```

原版这个方法只打一行 debug 日志、**不做任何校验**。这意味着：

> ⚠️ **玩家可以自己构造这个包**。
> 所以任何"改变状态"的动作都必须在路由层查权限/认证，
> 否则未登录玩家能直接触发你的逻辑。本项目的 `DialogRouter` 里有一张
> `AUTH_REQUIRED_PREFIXES` 名单就是干这个的。

**3. 不要在对话框回调里做重活**

回调在主线程。密码哈希（PBKDF2 一轮 25ms）、数据库查询都要丢到异步线程，
算完再 `server.execute(...)` 回主线程操作游戏状态。
本项目提供 `loginAsync` / `registerAsync` 就是为此。

## 表单元素

| 方法 | 用途 |
|---|---|
| `DialogKit.text("内容")` | 静态文本 |
| `DialogKit.textInput(key, 提示, 最大长度)` | 文本输入框 |
| `DialogKit.customButton(文字, 动作)` | 自定义动作按钮 |
| `DialogKit.submitButton(文字, 动作)` | 提交按钮（会带上表单数据） |
| `DialogKit.closeButton(文字)` | 关闭 |
| `DialogKit.form(common, 内容, 按钮)` | 多动作对话框 |
| `DialogKit.notice(common, 内容, 按钮)` | 纯提示框 |

## 读取玩家的输入

回传数据是个 `Payload`（包了 NBT），按你在 `Input` 里用的 key 取：

```java
DialogRouter.register(MY_ACTION, (player, payload) -> {
    String text = payload.getString("my_key");
    int number = payload.getInt("count");
    boolean flag = payload.getBoolean("confirm");
});
```

## 调试

```
/hub selftest
```

自检里有一项专门验证"对话框动作已注册"，以及**颜色码渲染**是否正确
（`&a` 和 `§a` 两种写法都要能出颜色，否则玩家会看到字面的 `&a`）。

如果表单弹不出来：先确认客户端没装屏蔽自定义界面的模组；
本项目的认证流程还保留了 `/login` `/register` 作为兜底通道。

## 附：箱子界面

要做"选项列表"（比如选服务器、选任务），**用箱子界面更简单也更稳**：

```java
ChestMenuScreen.open(player, "§l标题", List.of(
    ChestMenuScreen.Entry.of(
        new ItemStack(Items.DIAMOND_SWORD),
        "§f生存服",
        List.of("§7点我进入"),
        p -> PlayerRouter.sendTo(p, survivalWorld)),
    ChestMenuScreen.Entry.of(
        new ItemStack(Items.GRASS_BLOCK),
        "§a空岛服",
        List.of("§7点我进入"),
        p -> PlayerRouter.sendTo(p, skyblockWorld))
));
```

点击由 `ServerGamePacketListenerMenuMixin` 在 `handleContainerClick` 的
HEAD 处接管，**原版逻辑一点都不执行** —— 所以物品拿不走、
shift 点击/拖拽/数字键都没有副作用。

> 别忘了在玩家退出时调 `ChestMenuScreen.forget(uuid)` 清理状态，
> 否则那条 `UUID → 菜单` 记录会一直留着（闭包里捕获着 `ServerLevel`）。
