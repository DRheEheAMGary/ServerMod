## 1. 结论：进 0.5 有道理 —— 但按这个顺序走

1. **0.4 线到此为止**：不发正式版（已决定，next 停在 0.4.0-alpha.6）；
2. **0.5.0 = 客户端模组**（双端基础设施 + 物品迁移）；
3. **0.6.0 = 钓竿系统**（玩法 + 分层渲染 + 装配台 + 铁砧升级 + 断线/损坏 + 青金石附魔）。

### 为什么这么切（关键理由）

- 客户端模组决定**物品怎么注册、外观怎么渲染**；钓竿方案里的"120 个组合模型 + 借壳界面"
  在客户端模组落地后**全部作废**（改成运行时逐层渲染 + 自定义 Menu）。
- 先做钓竿 = 物品工作做两遍，还会生成一批注定删掉的模型 JSON。
- 两份方案文档自己也是这个顺序（客户端模组方案第 5 节）。

> 0.4 不发正式版的后果（已知并接受）：main 仍停在 0.3.0（上一个正式版）；
> 想开服的直接用 0.4.0-alpha.6。

## 5. 版本与分支（别忘）

- main = 正式版（0.4.0）／dev = 日常（0.5.0-SNAPSHOT）／next = 预发布（0.5.0-alpha.N）；
- 0.x **不保证**存档 / 配置兼容（见 AGENT.md）；
- 每个里程碑：dev 做完 → 合 next → 落版本号 → tag → Release。

## 6. 风险（按严重程度）

1. **强制安装客户端模组** = 玩家门槛最高的一项（长期不变）；「必须跟着更新」已用硬门槛 + 软区间消掉，剩下的是分发与更新的运维成本；
2. **去掉 Polymer 后没有兜底**：没装客户端看到的是未知物品 / 缺失模型（这正是"强制"的含义）；
3. **客户端渲染与界面服务端自检覆盖不到** → 每轮都要实机看（你验收 + 我 runClient）；
4. 钓竿系统的数值（耐久 / 速度 / 幸运 / 断线）需要实机调，首版别当定稿。
