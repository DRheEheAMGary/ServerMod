# HubSuite 架构与扩展

面向要改这个模组的人（未来的你）。本文说明**为什么这么设计**，
以及升级 Minecraft 时必须人工复查的地方。

---

## 1. 三句话概括

1. **每个子服 = 一个独立存档**（不是"一个存档里开三个维度"），因此规则、玩家数据、
   存档天然隔离；
2. **玩家切换子服 = 切换整套存档上下文**，所以不需要影子存储或搬运物品；
3. **新增子服只改配置**，`SubServer` 是接口，内置服和自定义服走完全相同的代码路径。

## 3. 多世界隔离是怎么做到的

### 3.1 存档隔离

`IsolatedSave.open()` 会为每个子服建一个独立的
`LevelStorageSource.LevelStorageAccess`，指向 `<服务端根目录>/hubsuite_<id>/`。
它带来三件独立的东西：

| 独立物 | 作用 |
|---|---|
| `level.dat`（`PrimaryLevelData`） | 独立的存档设置、时间、出生点 |
| `getDimensionPath()` | 独立的 `region/`、`entities/`、`poi/`、`data/` |
| `getLevelPath(PLAYER_DATA_DIR)` | 独立的 `players/data/` |

### 3.2 规则隔离（唯一的"必须 Mixin"点之一）

**26.1 的 gamerule 不再存在 `level.dat` 里**，而是全局一份挂在 `MinecraftServer`
（存在 `<world>/data/`）。原版 `ServerLevel.getGameRules()` 的实现就是一句
`return this.server.getGameRules();`。

做法：每个子服各建一份 `GameRules`，用 `ServerLevelGameRulesMixin` 在
`getGameRules()` 返回处替换。之所以只需这一个注入点，是因为已用字节码扫描确认
**原版所有游戏逻辑都通过 `level.getGameRules()` 取规则**（命令、进阶、重生、刷怪、
伤害、死亡掉落……），唯一的例外是 `DedicatedServer` 读全局的 advance-announce 开关。

### 3.3 玩家数据隔离（最容易被忽略的一点）

原版 `PlayerList` 自己持有一个 `playerIo`（构造时注入），目录固定在**主世界存档**的
`players/data/` 下。也就是说：

> **只给每个子服建独立存档目录，并不能分开背包。**
> 光看代码不会发现这一点，是内置自检实测抓出来的
> （玩家数据文件出现在了 `world/players/data/`）。

做法：`IsolatedSave.bindPlayerStorage()` 为每个存档建一个 `PlayerDataStorage`，
登记到 `PlayerDataRouter`；`PlayerListStorageMixin` 在
`PlayerList.save()` / `loadPlayerData()` 读取 `playerIo` 字段时替换成对应子服的那一份。

"当前是谁"由两条线索确定：

- **保存时**：玩家已在线 → 按他所在维度判断；
- **读档时**：玩家还没进世界 → 按预先登记的目标存档判断
  （`PlayerDataRouter.refreshPending()` 每 tick 刷新在线玩家的目标存档）。

## 4. Mixin 清单（升级 MC 时只需复查这 7 个）

| Mixin | 目标 | 为什么必须 |
|---|---|---|
| `MinecraftServerLevelsAccessor` | `MinecraftServer.levels` | 把我们创建的维度注册进去，让原版负责 tick/保存/追踪玩家 |
| `MinecraftServerStorageAccessor` | `MinecraftServer.storageSource` / `executor` | 两个字段是 protected/private，创建独立存档与新维度都要用 |
| `PlayerListAccessor` | `PlayerList.save(ServerPlayer)` | 自检需要走"和正常下线完全一样"的保存路径 |
| `PlayerListStorageMixin` | `PlayerList.playerIo` 字段读取 | ★ 玩家数据按子服隔离的关键 |
| `ServerLevelGameRulesMixin` | `ServerLevel.getGameRules()` | ★ gamerule 按子服隔离的关键 |
| `ServerCommonPacketListenerMixin` | `handleCustomClickAction` | 接收对话框表单提交（Fabric API 无此事件，原版实现只有一行 debug 日志） |
| `ServerGamePacketListenerCommandMixin` | `handleChatCommand` / `handleSignedChatCommand` | 命令闸门（Fabric API 没有"命令即将执行"事件） |
| `ConnectionChannelAccessor` | `Connection.channel` | 给假玩家注入 EmbeddedChannel，让 `isConnected()` 为真 |

> **约定（踩过坑）**：
> 1. Mixin 类里**不能有非 private 静态方法** —— 会抛
>    `InvalidMixinException: contains non-private static method`。
>    所以"注入状态"要用外部持有者类（如 `CommandGuardHolder`）。
> 2. **普通代码不能直接引用 `mixin` 包里的类** —— 会抛
>    `IllegalClassLoadError: is in a defined mixin package`。
>    所以 `ServerInternals` / `ServerLevelsAccess` / `PlayerListAccess` /
>    `CommandGuardHolder` 都放在业务包里，`mixin` 包里只留接口式 Mixin。

## 5. 扩展指南

### 5.1 加一个子服（不需要写代码）

在 `config/hubsuite/config.json` 的 `servers` 数组里加一条即可，字段含义见
[配置说明](配置说明.md)。重启服务端后：

- 自动创建独立存档 `hubsuite_<id>/`
- 自动创建维度 `hubsuite:server_<id>`
- 立即出现在 `/hub list`、`/hub <id>`
- 如果配了 `npc`，大厅里自动多一个假人

### 5.2 加一种空岛类型（不需要写代码）

在 `config/hubsuite/config.json` 的 `island.types` 里加一条：

```json
{
  "id": "nether",
  "displayName": "&c地狱空岛",
  "description": "&7下界岩小岛，出生就带烈焰粉",
  "layers": ["0:minecraft:netherrack", "-1:minecraft:netherrack", "-2:minecraft:blackstone"],
  "tree": false,
  "chest": true,
  "loot": ["minecraft:blaze_powder*4", "minecraft:flint_and_steel*1", "minecraft:obsidian*10"]
}
```

玩家即可用 `/island create nether`。

### 5.3 加一个新对话框（需要少量代码）

```java
// 1) 定义动作 id
public static final String ACTION_MY_FORM = "myplug/my_action";

// 2) 发给玩家
DialogKit.open(player, DialogKit.form(
        Component.literal("标题"),
        List.of(DialogKit.text(Component.literal("说明"))),
        List.of(DialogKit.textInput("content", Component.literal("输入"), "", 64)),
        List.of(DialogKit.submitButton(Component.literal("提交"), DialogKit.action(ACTION_MY_FORM))),
        DialogKit.closeButton(Component.literal("取消"))));

// 3) 接收提交（在 DialogRouter 里注册）
DialogRouter.register(ACTION_MY_FORM, (player, payload) -> {
    String content = payload.str("content");   // 输入框的值在这里
    // ... 处理
});
```

**要点**：按钮动作必须用 `CustomAll`（`DialogKit.customButton/submitButton` 已经封装），
它会把所有输入框的值按 key 合并进 NBT 负载回传。
不要用静态 `custom` 动作 —— 那种**带不回输入值**。

### 5.4 加一个新的世界生成方式（需要代码）

在 `HubSuiteConfig.WorldKind` 加枚举值，在 `WorldFactory.createStem()` 的 switch 里
补一个分支返回对应的 `ChunkGenerator`。不需要注册自定义生成器 ——
复用原版的（`FlatLevelSource`、`NoiseBasedChunkGenerator`）兼容性最好。

## 6. 验证方式

改完代码后：

```bash
./gradlew build                          # 编译
./scripts/dev-server.sh "hub selftest"   # 起真实服务端 + 跑 49 项自检
```

`hub selftest` 覆盖的正是"最容易悄悄坏掉"的部分：存档隔离、规则隔离、
玩家数据落盘位置、账号安全、空岛生成、集成适配。

**新增功能时请顺手加一条自检项** —— 这个项目的经验是：
多世界隔离这种东西，光读代码确认不了，必须实测。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| `gameTime` 全服共享 | 每个子服有自己的 `dayTime`（昼夜），但总游戏刻是同一个计数器 |
| 天气全局 | 下雨/雷暴在全服同步（`ADVANCE_WEATHER` 可按子服关掉） |
| 计分板全局 | `/scoreboard` 仍然是全服一份，未做按子服隔离 |
| 聊天全局 | 原版聊天广播是全服的，未做按子服隔离（26.1 移除了旧的聊天事件，需 Mixin） |
| 空岛重置是同步写方块 | 大岛重置会短暂卡顿；如需优化可改成异步分批 |
| 单方块空岛未实现 | 按需求只做了 classic 与 ocean |
| 假人皮肤依赖第三方接口 | 拉不到就用默认皮肤，不影响功能 |
