# 架构与扩展

面向开发者 / 想深度定制的服主：讲清**隔离是怎么做到的**，以及怎么加子服、岛型、任务、对话框。

---

## 1. 三句核心命题

1. 每个子服 = **一个独立存档**（不是「一个存档里开三个维度」），因此规则、玩家数据、地形天然隔离。
2. 玩家切换子服 = **切换整套存档上下文**，所以不需要影子存储 / 搬运物品。
3. 新增子服**只改配置**，内置服与自定义服走完全相同的代码路径。

技术栈：Minecraft 26.1.2 / Fabric Loader 0.19.5 / Fabric API 0.155.3+26.1.2 / Java 25。
26.1 起官方不再混淆，直接使用 Mojang 官方名（`ServerPlayer`、`Level`…），**没有 Yarn / Intermediary**，
build.gradle 里没有 mappings 行、也没有 remapJar。

## 3. 存档隔离

`IsolatedSave.open()` 为每个子服建一个独立的 `LevelStorageSource.LevelStorageAccess`，
指向 `<服务端根目录>/hubsuite_<id>/`，带来三件独立的东西：

1. `level.dat`（`PrimaryLevelData`）：独立存档设置、时间、出生点；
2. `getDimensionPath()`：独立 `region/`、`entities/`、`poi/`、`data/`；
3. `getLevelPath(PLAYER_DATA_DIR)`：独立 `players/data/`。

`level.dat` 采用原子写（先写 `.tmp` 再 move）。

## 4. 自定义维度 key 与注册

| 维度 | key |
|---|---|
| 大厅 | `hubsuite:lobby` |
| 普通子服主维度 | `hubsuite:server_<id>` |
| 子服下界 / 末地 | `hubsuite:<id>_nether` / `hubsuite:<id>_end` |
| 空岛大厅 | `hubsuite:skyblock_hub` |
| 经典空岛 | `hubsuite:skyblock_classic` |
| 海岛 | `hubsuite:skyblock_ocean` |

维度通过 `MinecraftServerLevelsAccessor` 写入 `MinecraftServer.levels`，注册后由原版负责
tick / 保存 / 追踪玩家。

> ⚠️ `MinecraftServer.levels` 是启动时一次性建立的**只读映射**，运行期无法卸载或新建维度。
> 因此**新增 / 删除子服必须重启**；重置地图只能删磁盘存档，重建交给下次启动。
> 三个子服也不能都用 `minecraft:overworld`（`levels` 按 key 唯一），所以用自有 key。

### 三种世界生成方式

`HubSuiteConfig.WorldKind`：

| 值 | 实现 |
|---|---|
| `normal` | 复用原版主世界区块生成器 |
| `flat` | `FlatLevelSource` + 配置的 `flatLayers` |
| `void` | 单层空气（原版内部 `voidGen=true`） |

**不注册任何自定义区块生成器**，兼容性最好。

## 5. 规则隔离

26.1 的 gamerule**不再存在 level.dat 里**，而是全局一份挂在 `MinecraftServer`（存 `<world>/data/`），
`ServerLevel.getGameRules()` 的实现就是 `return this.server.getGameRules();`。

做法：每个子服各建一份 `GameRules`，用 `ServerLevelGameRulesMixin` 在 `getGameRules()` 返回处替换。
之所以只需一个注入点，是因为已用字节码扫描确认原版所有游戏逻辑都通过 `level.getGameRules()` 取规则
（命令、进阶、重生、刷怪、伤害、死亡掉落……）。

规则持久化到 `config/hubsuite/rules/<子服id>.json`。

## 6. 玩家数据隔离（最关键、最容易漏）

原版把玩家数据分成**三份**保存，只做其中一份就会串：

| 数据 | 原版位置 | 隔离手段 |
|---|---|---|
| 背包 / 经验 / 末影箱 / 血量 / 饥饿 | `<存档>/players/data/<uuid>.dat` | `PlayerListStorageMixin` 替换 `PlayerList.playerIo` 的读写 |
| 成就 | `<存档>/players/data/advancements/<uuid>.json` | `PlayerListAuxDataMixin` 重定向路径 |
| 统计 | `<存档>/players/data/stats/<uuid>.json` | 同上 |

要点：

- `PlayerList` 自己持有一个 `playerIo`（构造时注入），目录固定在**主世界存档**下。
  只给每个子服建独立存档目录并**不能**分开背包 —— 这是内置自检抓出来的。
- 成就 / 统计的路径来自 `MinecraftServer.getWorldPath(...)`，与玩家维度无关；
  而且 `ServerStatsCounter` / `PlayerAdvancements` 把文件路径**烧死在字段里**，
  切换维度时必须把旧的那份存盘并从 `PlayerList` 缓存移除。
- 背包隔离是**两层**的，缺一不可：
  1. 内存暂存（`PlayerStateStash`）：切服时立刻套用目标维度那份；
  2. 磁盘文件：离开维度时强制落盘，进入内存里没有记录的维度时从文件读回。

> 历史坑：第一版只有内存层，关服时只调了 `clear()`，文件「只写不读」——
> 在生存服攒东西、重启、再进生存服背包就空了。现在 `checkStateSurvivesRestart` 自检钉住这条。

### 隔离范围一览

| 数据 | 位置 | 隔离方式 |
|---|---|---|
| 背包 / 经验 / 末影箱 / 血量 | `<子服存档>/players/data/<uuid>.dat` | `PlayerListStorageMixin` |
| 成就 / 统计 | `<子服存档>/players/data/{advancements,stats}/` | `PlayerListAuxDataMixin` |
| 世界存档（地形 / 方块 / 实体） | `hubsuite_<id>/` | 独立 `LevelStorageAccess` |
| 原版 gamerule | `config/hubsuite/rules/<id>.json` | `ServerLevelGameRulesMixin` |
| 位置记忆 | `config/hubsuite/last-locations.json` | 按「玩家 UUID × 子服」分键 |
| 空岛归属 | `config/hubsuite/skyblock/islands.json` | 按玩家 UUID |
| 任务进度 | `config/hubsuite/skyblock/quests.json` | 按玩家 UUID |
| 账号 | `config/hubsuite/accounts.db` | SQLite（不可用时 JSON 兜底） |

**全局共享**：聊天、Tab 列表（假人不显示）、玩家的**非家**传送（HuskHomes 的 tpa / warp / spawn，按配置）；
**家（/home）按子服真正分开**：存储加子服前缀（`integration/HomeNamespace` +
`HuskHomesHomeIsolation`），同名家可在不同子服各自存在。

## 7. 空岛服 = 一个子服、三个维度

| 维度 | 作用 |
|---|---|
| `hubsuite:skyblock_hub` | 公共大厅（平台 + 「选择岛屿」假人） |
| `hubsuite:skyblock_classic` | 经典空岛（网格方格，每人格子一座） |
| `hubsuite:skyblock_ocean` | 海岛（自然生成的海洋世界，岛按距离摆放） |

三个维度各有独立存档，玩家数据天然互不覆盖。

**入口分流**：进空岛服时 —— 上次在某个岛上 → 直接回那座岛；有岛但人在别处 → 回他最近玩的那种岛；
还没有岛 → 落到大厅，点假人选岛型。

海岛地形是自己写的噪声（`OceanWorldGenerator`）：一条 y 方向斜坡 + 两个尺度的噪声决定海床高度，
海床恒定落在海平面以下，所以永远不会冒出天然陆地；群系由同一条 continentalness 曲线驱动温度带与深浅。

## 8. Mixin 清单（22 个）

升级 Minecraft 版本时，**隔离关键**那 7 个必须逐行复查。

### 隔离关键

| Mixin | 目标 / 作用 |
|---|---|
| `PlayerListStorageMixin` | `PlayerList.playerIo` 读写 → 背包按子服隔离 |
| `ServerLevelGameRulesMixin` | `ServerLevel.getGameRules()` → 规则按子服隔离 |
| `PlayerListAuxDataMixin` | 成就 / 统计路径重定向 + 反射替换 `ServerPlayer` 的 final 引用 |
| `MinecraftServerLevelsAccessor` | 把自定义维度注册进 `MinecraftServer.levels` |
| `MinecraftServerStorageAccessor` | 访问 `storageSource` / `executor` |
| `PlayerListAccessor` | 自检走「和正常下线一样」的保存路径 |
| `PlayerListFieldAccessor` | 直读 `players` 原始字段（`getPlayers()` 会滤掉假人） |

### 世界 / 传送 / 重生成

| Mixin | 作用 |
|---|---|
| `ServerLevelSeedMixin` | 每维度用自己的地形种子（否则生存 / 创造是同一张地图） |
| `BaseFireBlockPortalMixin` | 自有维度里火能点燃下界门 |
| `PortalBlockDestinationMixin` | 每子服自己的下界 / 末地；出口门建在正确维度 |
| `ServerPlayerRespawnDimensionMixin` | 死亡重生落在当前子服 |
| `PrepareSpawnTaskMixin` | 登录直接落大厅（指定 ordinal，否则命中第二处会抛 ClassCastException） |
| `DistanceManagerRemovePlayerMixin` | 修原版对未登记区块的 NPE（切服「点进服务器没反应」） |
| `DistanceManagerAccessor` | 读 private `playersPerChunk` 做空值判断 |
| `StructureTemplatePaletteCacheMixin` | 修原版 `StructureTemplate$Palette` 缓存非线程安全（并行区块生成 CME） |

### 假玩家（NPC）

| Mixin | 作用 |
|---|---|
| `PlayerListFakePlayerMixin` | 假人不计入在线人数 / 列表 |
| `PlayerInfoListedMixin` | 假人不出现在客户端 Tab（`Entry.listed` 硬编码 true，只能改字段；不能删条目，客户端要靠它创建实体） |
| `ConnectionChannelAccessor` | 给假玩家注入 `EmbeddedChannel` |

### 数据包与交互

| Mixin | 作用 |
|---|---|
| `ServerCommonPacketListenerMixin` | 接收对话框表单提交（Fabric 无此事件） |
| `ServerGamePacketListenerCommandMixin` | 命令闸门（Fabric 无「命令即将执行」事件） |
| `ServerGamePacketListenerMenuMixin` | 接管箱子式菜单点击 |
| `BlockItemPlaceMixin` | 任务精确统计「放置方块」 |

### Mixin 约定（都踩过坑）

1. Mixin 类里**不能有非 private 静态方法** → `InvalidMixinException`。注入状态用外部持有者类。
2. 普通代码**不能直接引用 mixin 包里的类** → `IllegalClassLoadError`。
   helper（`ServerInternals` / `ServerLevelsAccess` / `PlayerListAccess` / `CommandGuardHolder`）放业务包。
3. `@ModifyExpressionValue` / `@At` 有多个匹配时要**指定 ordinal**。
4. 改 record 字段：`@Shadow @Final @Mutable`，且在构造器 `RETURN` 之后改。

## 9. 扩展指南

### 9.1 加一个子服（不需要写代码）

在 `config/hubsuite/config.json` 的 `servers` 数组里加一条，然后**重启**。

```json
{
  "id": "adventure",
  "displayName": "§6冒险服",
  "enabled": true,
  "order": 3,
  "worldKind": "normal",
  "seed": 20260606,
  "useWorldSpawn": true,
  "gameMode": "survival",
  "difficulty": "hard",
  "forceGameMode": true,
  "rememberLastLocation": true,
  "permissionGroup": "hubsuite.adventure"
}
```

重启后自动创建独立存档 `hubsuite_adventure/` 与维度 `hubsuite:server_adventure`，
立即出现在 `/hub list`、`/hub adventure`、`/menu`。

**踩坑**：

- 不要在运行中改 `id`（等于换新世界，旧存档还在磁盘但不再加载，改回去可恢复）。
- `worldKind` 从 `flat` 改成 `normal`（或反过来）必须删掉旧存档（维度类型在 `level.dat` 里）。
- 加完看启动日志，配置写错会看到「子服 'xxx' 加载失败，已跳过。」。

字段含义见 [配置说明](配置说明.md)。

### 9.2 加一种空岛类型（不需要写代码）

在 `island.types` 里加一条：

```json
{
  "id": "nether",
  "displayName": "&c地狱空岛",
  "description": "&7下界岩小岛，出生就带烈焰粉",
  "layers": ["0:minecraft:netherrack", "-1:minecraft:netherrack", "-2:minecraft:blackstone"],
  "tree": false,
  "chest": true,
  "loot": ["minecraft:blaze_powder*4", "minecraft:flint_and_steel*1", "minecraft:obsidian*10"]
}
```

玩家即可用 `/island nether` 建岛（界面上也会出现）。`layers` 格式为 `y偏移:方块id`。

> 经典空岛按**方格**判定保护（整格都算你的），海岛按**离岛距离**判定。
> 经典之所以按方格而不是地形：地形只有半径几格，方格有 `plotSize+plotGap` 格宽，
> 按地形判定玩家在自己方格内走远一点就会被拒。

### 9.3 加一个任务（不需要写代码）

任务在 `config.json` 的 `quests.quests` 数组里：

```json
{
  "id": "stone_64",
  "kind": "milestone",
  "name": "§7石匠入门",
  "description": "挖 64 个石头",
  "icon": "minecraft:stone",
  "goal": "break:minecraft:stone",
  "amount": 64,
  "rewards": ["minecraft:stone_pickaxe*1", "minecraft:bread*4"]
}
```

- `kind`：`milestone`（完成一次永久打勾）/ `deliver`（交物品换奖励，可反复）/ `daily`（每天重置）。
- `goal` 语法（`类型:参数`）：`break:<方块>`、`place:<方块>`、`kill:<生物>`、`have:<物品>`、
  `deliver:<物品>`、`reach_y:<高度>`、`enter:<子服>`。
- `rewards`：`物品id*数量`，数量省略为 1，自动夹到堆叠上限，背包放不下掉在脚下。
- 进度只在空岛相关维度累计；改定义后建议重启。

### 9.4 写一个对话框（需要代码）

原理：26.1 对话框是服务端下发、客户端渲染的原版机制。表单里的输入值会按 key 合并进动作的 NBT，
所以 `TextInput` 收集的内容**不进聊天、不进命令、不进日志**。

```java
private static final Identifier ACTION_LOGIN =
        Identifier.fromNamespaceAndPath("hubsuite", "auth/login");

DialogRouter.register(ACTION_LOGIN, (player, payload) -> {
    String password = payload.getString("password");   // 对应 Input 的 key
});

player.openDialog(DialogKit.form(
        DialogKit.common("§l登录", true, DialogAction.CLOSE),
        List.of(DialogKit.textInput("password", "§7请输入密码", 32)),
        List.of(DialogKit.submitButton("§a登录", ACTION_LOGIN))));
```

三个必须注意的点：

1. `after_action` 用 `CLOSE`，**不要用 `WAIT_FOR_RESPONSE`** —— 后者会让客户端进入等待态，
   之后约 5 秒点什么都点不动。
2. 动作必须走 `ServerCommonPacketListenerMixin` 拦截（Fabric 无「自定义点击动作」事件），
   而原版该方法只打一行 debug 日志、不做校验 —— 意味着玩家可自行构造这个包，
   任何改变状态的动作都要在路由层查权限 / 认证。
3. 回调在主线程，密码哈希、数据库查询要丢到异步线程，再 `server.execute(...)` 回主线程。

### 9.5 加一种世界生成方式（需要代码）

在 `HubSuiteConfig.WorldKind` 加枚举值，在 `WorldFactory` 的 switch 里补一个分支返回对应 `ChunkGenerator`。
优先复用原版生成器（兼容性最好）。

## 10. 已知限制

| 限制 | 说明 |
|---|---|
| `gameTime` 全服共享 | 每个子服有自己的 `dayTime`（昼夜），但总游戏刻是同一个计数器 |
| 天气全局 | 下雨 / 雷暴全服同步（可用 `ADVANCE_WEATHER` 按子服关掉） |
| 计分板全局 | `/scoreboard` 仍是全服一份，未按子服隔离 |
| 聊天全局 | 原版聊天广播是全服的，未按子服隔离 |
| 空岛重置是同步写方块 | 大岛重置会短暂卡顿 |
| 单方块空岛未实现 | 只做了 classic 与 ocean |
| 假人皮肤依赖第三方接口 | 拉不到就用默认皮肤，不影响功能 |
| `enter:` 任务目标暂未接线 | `Quest.GoalType.ENTER` 已定义、配置可解析，但没有事件把它接到进度上 |
| 爆炸 / 活塞不受空岛保护 | 默认 `plotGap=32` 时 TNT 半径够不到邻格，改小可能跨格 |
| `/auth` 与 `/hub selftest` 只认原版 OP 等级 2 | 不走 `hubsuite.admin` 节点 |
| 创造服作弊指令黑名单可被包装指令绕过 | 只取命令第一个词 |
